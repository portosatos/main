# Формат входных данных `ht.v1` (NDJSON)

Формат задан в SPEC §7.2. Здесь он описан подробно, вместе с тем, что пишет генератор `htgen` (SPEC F13).
Файлы загружаются через `POST /api/ingest/files` (шаг 3.2). Тот же формат записей используется в потоковом режиме:
JSON-массив в `POST /api/ingest/batch` (шаг 11.1).

## Строки

Файл — UTF-8, **одна JSON-запись на строку**. `htgen` пишет записи по времени и разделяет строки `\n`.
Допущение: порядок записей в файле не важен. Как парсер обрабатывает `\r\n` и пустые строки, решается на шаге 3.1.

| `type` | Поля | Смысл |
|---|---|---|
| `meta` | `schema`, `generator`, `devices` | Описание файла и устройств. Необязательна, если есть — первая строка |
| `steps` | `device`, `start`, `end`, `count` | Шаги за интервал `[start, end)` |
| `sleep` | `device`, `start`, `end` | Интервал сна `[start, end)` |
| `hr` | `device`, `ts`, `bpm` | Пульс в момент `ts` |

```json
{"type":"meta","schema":"ht.v1","generator":"htgen 0.1","devices":[{"id":"watch-1","kind":"watch","name":"Часы"},{"id":"phone-1","kind":"phone","name":"Телефон"}]}
{"type":"steps","device":"watch-1","start":"2026-10-01T08:00:30+03:00","end":"2026-10-01T08:01:30+03:00","count":112}
{"type":"steps","device":"phone-1","start":"2026-10-01T08:00:00+03:00","end":"2026-10-01T08:05:00+03:00","count":530}
{"type":"sleep","device":"watch-1","start":"2026-09-30T23:41:00+03:00","end":"2026-10-01T00:00:00+03:00"}
{"type":"sleep","device":"watch-1","start":"2026-10-01T00:00:00+03:00","end":"2026-10-01T07:12:00+03:00"}
{"type":"hr","device":"watch-1","ts":"2026-10-01T08:00:05+03:00","bpm":96}
```

### `meta`
- `schema` — `"ht.v1"`; `generator` — кто записал файл (у `htgen`: `"htgen 0.1"`).
- `devices` — список `{"id", "kind", "name"}`. `id` — внешний идентификатор устройства (`external_id`, SPEC F2),
  `kind` — `watch` или `phone`, `name` — имя для интерфейса.
- Устройство создаётся при первой встрече в данных, тип берётся из `meta`. Если устройства нет в `meta` (или
  нет самой `meta`), оно создаётся с типом `phone`, а в отчёт загрузки попадает предупреждение (SPEC §7.2).

### Метки времени
- ISO 8601 **обязательно со смещением**: `2026-10-01T08:00:30+03:00` или `...Z`, допускаются секунды.
  Метка без смещения — ошибка строки (`invalid`).
- Смещение нужно только для перевода в UTC: в БД всё хранится в UTC (SPEC F4). Локальные даты считаются по истории
  поясов пользователя, а не по смещениям в файле (SPEC F5).
- Интервалы полуоткрытые: `[start, end)`. Соседние интервалы одного устройства (`end` одного = `start` другого)
  не пересекаются.

## Валидация (класс `invalid`, SPEC §7.2)
- Строка — корректный JSON-объект с известным `type` и нужными полями.
- `steps` и `sleep`: `end > start`, интервал не длиннее 24 ч; `count` — целое, `count ≥ 0`.
- `hr`: `bpm` — целое, `30 ≤ bpm ≤ 230`.
- Строки, которые не прошли проверку, отклоняются. Загрузку они не роняют.

## Что пишет `htgen`

```bash
uv run --project generator htgen --days 7 --seed 1 --out sample.ndjson
uv run --project generator htgen --help
```

| Опция | По умолчанию | Смысл |
|---|---|---|
| `--start`, `--end`, `--days` | 7 дней до вчера | Период: локальные даты включительно. Можно задать любые две опции из трёх. Если указан только `--days`, период заканчивается вчера (последний полный день). Если указана одна граница, берётся 7 дней |
| `--devices` | `watch,phone` | Какие устройства писать |
| `--seed` | `0` | Seed: одинаковые аргументы дают побайтно одинаковый файл |
| `--hr-interval` | `5` | Шаг пульса часов, секунды (1–3600) |
| `--unaligned` | выкл. | Сетка интервалов шагов сдвинута на 1–59 с от начала минуты (одинаково для часов и телефона, свой сдвиг на каждый день) |
| `--tz` | `Europe/Moscow` | Пояс IANA в начале периода |
| `--tz-change МОМЕНТ=ПОЯС` | нет | С этого момента действует другой пояс: `2026-10-05T12:00Z=America/New_York`. Момент — со смещением или `Z`. Можно повторять |
| `--gap ОТ/ДО[@watch\|@phone]` | нет | Явный пропуск: `2026-10-03T00:00/2026-10-04T12:00@watch`. Время без смещения — местное (по `--tz` и `--tz-change`), без `@` — пропуск у всех устройств. Можно повторять |
| `--gap-prob P` | `0` | Вероятность, что у устройства в эту дату начнётся случайный пропуск |
| `--gap-max-hours H` | `30` | Самый длинный случайный пропуск, часы; самый короткий — 1 ч |
| `--scenario ИМЯ[,ИМЯ]` | нет | Заготовка данных для правил в конце периода (см. ниже). Можно повторять |
| `--out` | `-` (stdout) | Файл NDJSON. Всегда UTF-8 и LF, на Windows тоже. В Windows PowerShell 5.1 файл пишите через `--out`, а не через `>`: `>` перекодирует вывод в UTF-16 |

Без опций шага 2.2 (пояса, пропуски, сценарии) файл побайтно тот же, что выдавала версия шага 2.1.
`--stream` появится на шаге 11.1.

**Часы (`watch-1`):**
- шаги — интервал на каждую минуту бодрствования, в том числе с `count: 0`;
- пульс — круглые сутки, каждые `--hr-interval` секунд, кроме пропусков;
- сон — отбой между 22:30 и 00:30, длительность от 6,5 до 8,5 ч.

**Телефон (`phone-1`):**
- шаги — интервалы по 5 минут во время бодрствования. На прогулке телефон насчитывает 90–97% шагов часов, в остальное
  время 40–80% (телефон не всегда в кармане);
- сон — границы смещены от часов на ±20 мин;
- пульса нет.

**Суточный профиль:** 1–3 прогулки по 15–60 мин в темпе 95–125 шагов в минуту (с 07:00 до 21:30), 2–3 сидячих
периода по 60–150 мин без шагов (с 08:30 до 20:00), остальное время — лёгкая активность (в 30% минут от 5 до 40
шагов).

**Детерминизм и границы:**
- все случайные значения даты D берутся из генератора с seed `(seed, D, назначение)`. Каждая запись лежит внутри
  своих суток `[D 00:00, D+1 00:00)` по местному времени. Поэтому дата D в любом периоде, который её содержит,
  выглядит одинаково;
- по той же причине **сон, который переходит через полночь, записывается двумя соседними интервалами**:
  `[отбой, 00:00)` и `[00:00, подъём)`. Объединение минут сна (SPEC F4, F5) склеивает их в одну сессию;
- первая ночь периода начинается в 00:00 первого дня, если отбой был накануне. Последний вечер заканчивается
  в 00:00 после последнего дня;
- интервалы шагов одного устройства никогда не пересекаются. Конфликтов (SPEC F4.2) генератор не создаёт.

**Часовые пояса** (`--tz`, `--tz-change`):
- у каждой метки смещение того пояса, который действует в этот момент. Интервал, через который прошла смена,
  получает `start` со старым смещением и `end` с новым;
- дата длится от первого момента этой местной даты до первого момента следующей. Поэтому день переезда
  длиннее или короче 24 ч: Москва → Нью-Йорк в 12:00Z — 31 ч, назад — 17 ч. Записи идут подряд, ничего
  не теряется и не удваивается. Отбой, подъём и прогулки отсчитываются от начала окна даты: после переезда
  человек спит ночью по новому поясу;
- если ночи короткого дня перекрываются, сон устройства пишется одним интервалом.

**Пропуски** (`--gap`, `--gap-prob`, `--gap-max-hours`):
- в пропуске устройство не пишет **ничего**: ни шагов, ни сна, ни пульса. Сон обрезается по границам пропуска,
  шаги после пропуска идут с его конца (у телефона — новые 5-минутные интервалы);
- случайный пропуск начинается в дату D у устройства с вероятностью `--gap-prob`, в случайную минуту окна даты,
  и длится от 1 ч до `--gap-max-hours` (может уйти в следующие даты). Значения берутся из генератора с seed
  `(seed, D, "gap:<устройство>")`. Пропуски одного устройства не перекрываются и отстоят друг от друга
  минимум на 1 ч: пропуск отменяется, если в него заходит пропуск, выпавший в одну из предыдущих дат;
- дата учитывает пропуски, начатые в предыдущие даты, даже до начала периода. Поэтому повторный запуск с тем же
  seed на пересекающийся период даёт те же записи в пересечении (это нужно для проверки дедупликации).

**Сценарии** (`--scenario`) — данные для правил SPEC F9, отсчитываются от конца периода. При загрузке файла,
который заканчивается вчера, правило срабатывает (или закрывается) на ближайшей оценке:

| Сценарий | Правило | Что меняется | Мин. дней |
|---|---|---|---|
| `short-sleep` | R1 | Последние 3 ночи по 4,5–5,5 ч | 4 |
| `sedentary` | R2, R6 | Последние 5 дней без прогулок, лёгкой активности мало: меньше 4000 шагов, нет минут от 100 шагов | 5 |
| `high-rhr` | R3 | Последние 2 дня пульс выше обычного примерно на 12 уд/мин | 9 |
| `irregular` | R5 | Последние 7 отбоев с 20:30 до 02:30 (стандартное отклонение около 120 мин) | 8 |
| `worse-week` | R4 | В последней полной ISO-неделе периода (пн–вс) сон 5–6,5 ч | 2 полные ISO-недели |
| `recovery` | R1–R6, закрытие | Последние 7 ночей и последняя полная ISO-неделя — 7,5–8,5 ч с отбоем 23:15–23:45; последние 3 дня — прогулка 60–90 мин от 105 шагов в минуту; последние 2 дня — низкий пульс | 1 |

Сценарии можно сочетать (`--scenario short-sleep,high-rhr`), `recovery` — только отдельно. Слишком короткий период
для сценария → exit 2. Значения сценариев берутся из своих генераторов, поэтому даты, которые сценарий не трогает,
совпадают с файлом без него. Записи в пересечении двух периодов одинаковы, если у периодов общий конец
или сценария нет.

**Объём:** при `--hr-interval 5` пульс даёт 17 280 строк в сутки. Неделя — около 130 тыс. строк и 10 МБ.
