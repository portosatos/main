## Кандидаты

### Параллельная обработка разных пользователей в стеке по умолчанию (шаг 3.2, ADR-031)
- **Сейчас:** в `docker-compose.yml` один процесс воркера, а он берёт одну задачу за раз. Поэтому в стеке по
  умолчанию задачи разных пользователей тоже идут по очереди: большой файл одного пользователя задерживает
  загрузку другого. Код к параллельности готов (`SKIP LOCKED` и advisory lock по пользователю, тест
  `test_same_user_jobs_sequential_different_users_parallel` с тремя воркерами), но её даёт только запуск
  нескольких процессов: `docker compose up -d --scale worker=2` (на стеке не проверялось).
- **Варианты:** несколько воркеров в compose по умолчанию (`deploy.replicas`); или N параллельных задач внутри
  одного процесса воркера (по соединению с advisory lock на задачу).
- **Учесть:** нагрузку на Postgres при нескольких одновременных загрузках; `worker_id` у реплик (сейчас
  `hostname-pid`, у реплик hostname разный).
